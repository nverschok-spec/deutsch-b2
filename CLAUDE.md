# Как мы работаем над этим проектом

## 1. Цикл на каждую задачу
Реализовал → собрал (`npm run build`, проверил на ошибки/warnings) → закоммитил в git с внятным сообщением → запушил → задеплоил → сам проверил, что реально работает (curl / реальное устройство — не "код выглядит правильно").

Не переходить к следующей задаче, пока предыдущая не подтверждена рабочей.

## 2. Git-дисциплина
- Коммит — не amend, всегда новый.
- Сообщение коммита объясняет "почему", а не пересказывает диф.
- Никаких force-push, `reset --hard`, удаления веток без явного разрешения.
- Перед любой потенциально разрушительной операцией — `git status`, чтобы не потерять несохранённое.

## 3. Деньги и инфраструктура
- Никогда не подключать платный тариф/сервис без явного согласия.
- Если сервис "бесплатный" — сначала проверить реальные лимиты и как они соотносятся с реальной нагрузкой, а не с одним замером использования в моменте. Разовый снимок — не гарантия на весь месяц.
- Если платный барьер всё же встретился — по умолчанию искать способ остаться в бесплатных рамках (переархитектурить), а не сразу платить.

## 4. Стиль кода
- Без лишних комментариев — только там, где неочевидна причина ("почему", а не "что").
- Не добавлять функциональность/абстракции сверх того, что просили.
- При чисто визуальных/UI-правках не трогать бизнес-логику, если не попросили отдельно.
- Три похожие строчки — лучше, чем преждевременная абстракция.

## 5. Отладка
- При сбое — искать первопричину через реальную диагностику (логи, curl, прямые запросы к API/базе), а не гадать и чинить наугад.
- После фикса — обязательно перепроверить вживую, не считать задачу закрытой по одному тесту "похоже, заработало".

## 6. Общение
- Коротко, по делу, без предисловий и лишнего пересказа.
- Если для решения нужен явный выбор пользователя (деньги, необратимое действие, неоднозначная цель) — сначала спросить, не выбирать самому.
- Во всём остальном — действовать автономно пачками, не переспрашивать на каждый шаг.

## 7. Изоляция проектов
- У каждого проекта — своя папка, свой git-репозиторий, свой деплой.
- Не путать и не трогать один проект, работая над другим, даже если они лежат рядом на диске.

## 8. Мобильный/PWA-специфика
Этот проект — PWA, всегда держать в уме:
- iOS Safari: зум при фокусе на инпутах с `font-size < 16px` — все инпуты/textarea минимум `text-base` (16px).
- Статус-бар/notch: отдельные мета-теги (`viewport-fit=cover`, `theme-color`) + `env(safe-area-inset-*)` отступы (уже используется в `index.html`/`index.css`, не убирать при правках).
- Service worker кэширует агрессивно — после деплоя иногда нужно полное закрытие/переоткрытие приложения или переустановка иконки, а не просто reload. Если фикс "не применился" на телефоне — сначала проверить это, а не откатывать код.
- Анимации — 150-250мс, только `transform`/`opacity` (не layout-свойства), с поддержкой `prefers-reduced-motion`.

## Контекст проекта (кратко)
Deutsch B2 — PWA для подготовки B1→B2 и Umschulung. React 18 + Vite + Tailwind, Zustand (persist в LocalStorage), Vercel serverless (`api/claude.js`, единственное место с `ANTHROPIC_API_KEY`) → Anthropic `claude-haiku-4-5`, Web Speech API для голоса. Архитектура и что уже сделано/не сделано — см. `README.md` в этой же папке.
